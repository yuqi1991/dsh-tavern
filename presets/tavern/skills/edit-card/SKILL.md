# 修改人物卡

目标是完成用户指定的局部修改，保留其余内容。人物卡及其实际绑定的世界书共同构成编辑范围，按需求读取相关条目。使用当前引用的目标人物卡；目标或修改要求不明确时，只询问缺失的信息。目标明确就开始执行。

## 读取与选择工具

先用一句话说明本次要改什么、正在读取哪部分。只读取目标字段，需要关联证据时再扩大范围。

- 没有 `dsh_mvu_conversion` 转换元数据的 MVU 卡（用 `tavern_apply_mvu` 加的或导入的）：先 `tavern_mvu_overview` 看全貌，变量、规则、面板用 `tavern_apply_mvu` 只传要改的部分，或像普通文件一样直接改；改完看附带的校验。带转换元数据的卡不能用 `tavern_apply_mvu`，走下一条。
- 已有 MVU 卡的变量增删、改名、移动或开场初值：先按下方关联世界书规则识别定义归属；托管卡读取 [变量修改配方](references/mvu-variables.md)，用 tavern_card_draft 的 begin path 载入目标定义并局部修改。
- 仅修改已有 MVU 面板的标签、重复字段名、布局或样式，且没有进行中的变量草稿：调用 `tavern_read_mvu_appearance`，参数 `path` 为目标副本。`editable=true` 时走下方美化流程。
- 普通设定、开场和文风：用 `tavern_read_card` 读取相关字段，通过 `tavern_update_card` 保存需要的变更，再用 `tavern_validate_card` 校验。原地 MVU 卡（元数据 `selfSourced=true`）以卡片文本为准，像改普通文件一样直接改：改开场正文时只写剧情文字，工具自动保留末尾的 `<initvar>` 与状态入口；只改某个开场的初值，也可以直接改该 `<initvar>` 里的 JSON 值，保持合法 JSON。增删变量字段或开场会牵动面板和各开场，改用 tavern_card_draft 的 begin path。
- 定位：不确定要改的内容在哪，或要改多处时，先用 `tavern_search_card` 一次搜遍全卡（标准字段、开场、世界书标题/关键词/正文、正则、脚本），按返回的位置读取和修改，不必写脚本翻 JSON。
- 改名、统一措辞等同一段文字要改多处时：`tavern_replace_card_text` 一次替换全卡并保存，结果列出每处位置和全卡剩余处数；只改部分位置时用 `pointers` 限定，`expectedCount` 可防止替换范围超出预期。
- 美化返回 `editable=false`：按返回说明读取目标卡相关扩展。普通正则美化使用通用改卡工具；已转换卡出现方案外修改、缺失定义或来源固化美化时，先说明具体限制和保留方案，不把生成元数据当普通扩展直接修改。
- 用户要求转换为 MVU：通过原生 `skill` 加载 `card-to-mvu`。用户提供游玩故障证据并要求诊断时加载 `debug-card`。

Skill 入口由原生 `skill` 加载，参考文件通过 `tavern_read_skill_reference` 按需读取。常规编辑使用资源工具，无需搜索磁盘上的 Skill 目录、其他人物卡或工具源码。只有现有工具确实无法表达用户要求时，才说明缺口并采用限定目标文件的备用方案。

## 关联世界书与变量定义

修改变量、世界设定或更新规则时，先确认目标卡实际绑定的世界书，以及定义所在的条目或脚本。初值可能位于 `[initvar]` 条目或开场 `<initvar>`；更新规则、结构约束、面板绑定可能分布在不同位置，不能仅根据人物卡表面字段判断是否改完。

- 用 `tavern_read_worldbook` 按 query、ref 或分页读取相关条目。path 省略仅适用于当前会话绑定卡就是本次目标；其他目标应先查明其实际世界书路径，再显式传 path。独立世界书为 `worldbooks/...`，内置世界书为 `cards/...`。不要假定内置内容与外部绑定内容相同。
- 托管 MVU 卡：以保存的定义为修改入口，沿用变量配方和草稿 commit，同步生成初值、规则与绑定。工具已返回的定义无需逐条重复读取；只有归属不明、规则依赖或一致性问题才补读世界书。不要另用通用世界书工具改写托管生成条目，造成方案与成品不一致。
- 外部 MVU 卡：先定位初值、更新规则和结构脚本的真实来源。现有托管草稿不代表支持任意外部结构；只在相关格式及依赖已明确、现有工具能表达修改时局部处理。脚本约束无法可靠同步时报告具体缺口，保留原卡，不强行重新转换。
- 普通世界书条目：根据已读 ref 使用 `tavern_update_worldbook` 的条目级 operations，保留其他条目。用户已经明确要求的目标修改无需重复确认；授权范围未包含的其他卡或共享资源效果需先说明。
- 独立世界书可能被多卡共用。修改前查绑定信息；工具未提供反向引用清单时，只检查相关资源绑定元数据，不遍历其他卡正文。仅凭当前卡绑定它，不能认定独占。用户仅要求修改当前卡时，优先在现有能力允许下建立独立副本并只重绑目标卡；共享关系无法确认或工具无法安全隔离时，说明具体影响并询问是否修改共享资源，先完成其他独立修改。

保存后核对本次涉及的定义、开场、规则与展示引用是否一致。通用人物卡格式校验通过不等于外部结构脚本或存档兼容性已验证。报告实际修改的卡片和世界书范围；资源保存不等于已更新正在游玩的存档，应用本局更新按变量配方执行。

## 局部美化流程

1. 读取返回的 HTML 与 bindings；需要未返回的片段时，按 `html.nextOffset` 续读并携带同一个 `revision`。外层已有字段名、值前又出现路径标签时，删除多余的静态标签，保留值占位与绑定。
2. 简短说明已定位的问题和准备修改的内容，例如“日期前多了一段路径标签，正在移除”。调用 `tavern_update_mvu_appearance`，提交 `path`、`revision`、`replacements:[{expected,value}]`。每项 expected 都是当前 HTML 中恰好出现一次的片段；多项以同一版本为准且不重叠。不需要回传整卡、初值或脚本。
3. 提交前说明“正在保存并校验”。工具负责同步定义、生成面板和摘要；成功且 `validation.valid=true` 即完成。无需另行读取全部生成物、再次转换或重复校验。

版本冲突时重新读取目标；匹配失败时扩大唯一原文片段。按错误中的具体字段修正，不重复提交相同失败参数。保留全部 `$N` 占位及 bindings；仅改文案不改变量定义或开场状态。

## 完成与进度

阶段变化时用简短正文告知用户正在做什么；过程较长时补充已完成的工作和当前原因，不编造百分比或预计时间。遇到工具限制明确报告，避免无反馈地扩展搜索。

保存并自动校验通过后，说明改动和结果即可。静态校验没有覆盖的浏览器布局或剧情效果可以作为范围说明，不能列为必须完成的“待真实验收”；只有用户明确要求才做真实游玩测试。
