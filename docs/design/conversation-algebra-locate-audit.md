# 会话操作不因定位失败而被拒绝：审计与改造记录

- 日期：2026-10-29（分支 upgrade/dsh-0.2.1，DSH 0.2.1-rc.2）
- 关联：`conversation-algebra.md` §3.1.1 / §6.3、ADR-0008、ADR-0009、`CONTEXT.md`（Floor Projection）
- 行号以审计起点提交 `fd4e486e` 为准；现状行号随改动已有位移。

## 不变式

> 回退、重新生成、编辑正文、撤销回退、切换变体因为"找不到对应的行、轮次号对不上、步骤错位"而无法精确定位时，不得拒绝；以日志为权威重新计算目标，用 `select`（或原有的编辑事务）把操作做成。

与上游（`flizzywine/dsh-tavern`，`docs/design/native-session-repair.md`）的取舍不同：上游以 Chat 为权威，对原生 surface 做"最长一致前缀 + 尾部重写"的修复；本 fork 的 Chat 只是正文镜像，**日志是内容的唯一事实源**，所以：

1. 楼层按**位置**定位（楼层投影给出该层当前的输入行和正文行），不按原生轮次号做算术；轮次号只在投影映射不了的日志上作兜底。
2. 修复动作就是一次普通的 `select` 或 `editStep`，不新增"为定位而写"的簿记行、修复原语或第二张表。
3. 只有"会损坏数据"的情形继续拒绝：事务冲突、并发写、恢复计划与日志不符、工具配对被拆、压缩摘要可能带着已回退的剧情等。

## 改造点：复现测试 → 修复

全部复现测试在 `tests/algebra/floor-location.test.mjs`，夹具是 `tests/algebra/locate-harness.mjs`（真实宿主 Session + 补丁 + Story Timeline Chat，真实调用 `createRoundHistory` / `createBodyEditor`，可注入"缺 tavernStoryTurn"、孤儿轮、日志外选择、写入前崩溃、半截事务）。

1. **切换变体后编辑正文**：重新生成 → 切回旧变体 → 编辑正文，旧代码报"最后一轮正文已不在当前上下文中"（楼层以最新生成轮承载，活动正文在旧轮）。→ `locateFloorBody`（`rollback-surface.js`）取楼层投影的当前正文行，`body-editor.js`、`round-history.js` 的重新生成目标共用。
2. **缺 `tavernStoryTurn` 的编辑正文**（0.2.1 编辑步骤有自己的轮次号；标记出现前写的会话没有）：编辑后再回退/重新生成/再编辑。→ 同上；`withStoryTurn` 沿改写链回溯到开启剧情轮次的原回复，早期编辑缺标记时再次编辑也写对标记（`story-turn.js` `originStoryTurn`）。
3. **混合轮次的尾部回退**：带工具步骤的楼层 + 缺标记的编辑正文，旧代码报"回退消息归属不一致，无法安全清理"。→ 回退不再要求归属一致的区间。
4. **日志比聊天多一个已完成的孤儿轮**：回退目标由聊天末层的输入位置决定，孤儿轮随同一次选择离开，撤销可回到原样。
5. **日志已离开聊天末层**（聊天比日志多）：证明 surface 停在该楼层之前（非空、无压缩摘要、无同轮或更晚的行）才只退聊天，并保留 branch + 自选择以便撤销；压缩摘要在场时仍拒绝（仍可能带着该层剧情）。
6. **checkout 锚点被别的线上的编辑"遮住"**：编辑 → 切走 → 切回 → 新一层 → 回退，报"checkout 锚点不在当前分支"。→ surface 上的锚点直接用。
7. **重新生成被中断后挡住所有操作**：
   - 提交后、结算前切换了变体 → 恢复时目标已离开 surface，预检报错、标记永远清不掉；
   - 预切出意图已持久化而 `select` 未落日志 → 恢复报"checkout ref 无效"；
   - 日志丢了未刷盘的尾部 → 恢复报"边界不匹配"；
   - 回退、编辑正文遇到遗留标记直接提示等待。
   → 恢复前置到回退/重放/编辑，丢弃从未落地的意图，边界取日志末尾，只结算仍在 surface 上的节点。
8. **诊断**：仍被拒绝的情形（压缩边界、楼层无法映射、楼层不在 surface 上）写结构化记录 `rollback-target` / `body-edit-target`（与已有的 `regeneration-target` 同一机制，不含正文）。

不变的约束：所有写入仍走 `runTransaction` / `writeSurfaceEvent` / 代数的 checkout；没有新增事件类型、簿记行或手工同步表（架构守卫 `tests/algebra/architecture-guard.test.mjs` 全过）。

## 需要产品决策的点

**P1 聊天有该楼层、日志已离开它时，重新生成和编辑正文怎么办？**（回退已能做，所以玩家有出路）当前保守：拒绝并提示"可先回退这一层再继续"，记诊断。选项：
- A（当前）拒绝，先回退。
- B 编辑只改聊天文本：楼层本来就不在模型上下文里，改了不影响模型；但日志里没有这份内容，以后在上下文里出现的版本与聊天不一致。
- C 重新生成时把聊天里的输入作为新的输入行追加，再生成，不退役这条输入（它就是该楼层的输入）。

**P2 全局轮次号偏移**（宿主"轮次修复"让整个日志相对聊天整体错一位，见 `agent-lookup.js` 的说明）：按轮次号映射的楼层全部落空，所有操作拒绝（诊断 reason 为 `floor-not-mappable`）。可行方案：聊天楼层与存活楼层从尾部按顺序配对，要求偏移恒定并用正文文本逐层核对后才采用。没做，因为不核对文本会把"孤儿轮"误当成偏移。

**P3 编辑已保存变体后离开**（真实 e2e 发现）：编辑写在活动线上，变体槽仍指向编辑前的分支头；离开后编辑还在日志里，但回到该槽看到的是编辑前的正文，编辑不在任何槽里。选项：编辑时更新该变体的分支头 / 离开时把编辑线归档为新变体 / 维持现状。不是拒绝问题，未改。

**P4 分叉**：宿主按 seq 分叉，分叉点之后才发生的编辑带不过去，当前拒绝。选项：分叉后在新会话里补一次 `select`/`editStep` 对齐；或维持拒绝。

**P5 重新生成把孤儿轮存成该楼层的变体**（离线复现，改动前同样如此）：日志里有聊天不知道的孤儿轮时重新生成，预切出把孤儿轮连同旧正文存进分支；分支带该楼层的轮次标签，变体按分支末尾的正文取文，于是该楼层的变体列表里是孤儿轮的正文，原正文只剩日志（分支里仍可回到）。选项：重新生成前先选择去掉孤儿轮（不打标签、不存变体）；或让变体取分支头里该楼层自己的正文。
**P6 Chat-only 回退**（上面第 5 点）是否接受？不接受只需让 `floorRollbackTarget` 在该分支返回 `refusal: 'floor-not-mappable'`。

## 遗留风险

- R1 失败回合清理仍要求可证明的区间（见表）；如线上出现，把 `clearFailedTurnSurface` 回退成"选择去掉自有节点"。
- R2 重新生成中断后玩家已在预切线上继续，恢复仍拒绝清理（保护新内容），回退/重新生成会因此报错。需要产品决定"放弃那次重新生成并丢弃未完成的存档回滚"是否可接受。
- R3 全局轮次偏移（P2）未处理。
- R4 `switchVariant` 不先恢复遗留的重新生成标记（与其它操作不一致，未发现后果）。
- R5 e2e 的 `--surface-recovery` 场景本次运行起步就失败（`openStatus` 被侧栏页签拦截点击）。本次没改客户端，推断为 0.2.1 上既有的问题，但没有在基线上单独复核；未修，定位类步骤因此加在 normal 流程。
