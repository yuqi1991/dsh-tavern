# ADR 0008：重新生成分支化——变体即分支

- 状态：接受（取代 ADR 0005）
- 日期：2026-09-30

## 背景

ADR 0005 取消 Swipe 的理由是：把多版本正文映射进持续 Session 会让 Chat 当前选择、模型可见 Surface 与后台结算三分叉，并发一致性无法保证。该诊断正确，但"删除多版本"是过量的药——分叉的根源是**平行数组 + 双写**，不是多版本本身。

会话操作代数（`docs/design/conversation-algebra.md`）建立了单一事实源之后，ADR 0005 拒绝的场景在结构上不再成立：

- 消息内容只有事件日志一份；分支是日志上的指针，不存在第二份真相（杀 B7 类双写）。
- 重生成 = `branch + checkout(锚点) + generate()`：旧正文保存为命名分支（变体），生成发生在干净前缀上；中止恢复 checkout 回旧线，任何时刻只有一条活跃线（杀"当前选择与 Surface 分叉"）。
- 结算绑定 branch/revision（ADR 0006 规则不变），迟到结果 stale 即弃。

阶段 1 实测（session-ebefd02d 白名单）：前置 checkout 的重生成、中止恢复、回退/撤销撤销、重复重生成均已部署验收；每次重生成自动归档旧正文为兄弟分支，分支注册表与 Chat 投影双向一致。

## 决定

1. 重新生成保留多版本能力：每次重生成把被替换正文保存为同锚点兄弟分支（自动命名+时间戳），不删除。
2. 活跃版本由分支指针决定；切换变体 = `checkout`（阶段 2 提供产品 UI，规格 §9：仅最后一条 assistant 消息显示 `‹ n/m ›`）。
3. 手动分支清理是唯一销毁路径（D3：默认全留，永不自动删 active）。
4. ADR 0005 的"生成失败恢复旧正文、后台失败保留新正文"边界（现 ADR 0006）不变。

## 结果

- 用户重新获得多正文候选；旧正文永不丢失，回旧线零模型费用。
- Chat/Surface/结算不再因多版本分叉：三者都从同一 fold 派生或绑定分支版本。
- 旧 Swipe 兼容字段（`swipes[]/swipeId`）保留为导入兼容读，不再作为产品语义；其删除与 `replaceLastRound` 收编属阶段 2（chat 去镜像后）。
- 本 ADR 随阶段 1 切片落地；变体切换 UI 与 MVU 变体级联动（D1）在阶段 2 交付。
